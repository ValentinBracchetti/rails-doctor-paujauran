Ce que ça veut dire

Votre application fonctionne, mais elle accumule des risques de sécurité et des freins techniques qui coûteront plus cher à corriger demain. Sans intervention, les coûts de maintenance et le risque d'incidents augmenteront sensiblement. Une action rapide sur les points critiques est recommandée.

Les 5 risques principaux

Vulnérabilité critique dans GraphQL (exécution de code à distance)

Une faille de sécurité connue dans la bibliothèque GraphQL permet à un attaquant de prendre le contrôle du serveur. La correction est simple (mise à jour) et urgente.

Données non chiffrées en production

Le chiffrement SSL (HTTPS) est désactivé. Les mots de passe, tokens et données sensibles peuvent être interceptés lors de leur transmission.

Plus de 40 vulnérabilités dans les bibliothèques

Les composants logiciels (Rails, ActiveAdmin, Puma, etc.) contiennent des failles de sécurité connues. Votre application n'est plus couverte par les mises à jour de sécurité depuis 2023.

Absence de tests sur les fonctionnalités critiques

Moins de 10 % du code est couvert par des tests. Chaque mise en production comporte un risque de régression non détectée.

Performance dégradée sous charge

L'application n'est pas équipée pour détecter les requêtes inefficaces (N+1). Le cache n'est pas configuré en production. Les listes de commandes et clients peuvent devenir lentes avec la croissance des données.

Notre recommandation

Nous recommandons de commencer par le Lot 1 — Quick Wins (5 jours) pour un investissement de 2 500€ à 5 000€. Cette première phase corrige les risques les plus critiques : activation du SSL, mise à jour de GraphQL, configuration du cache, détection des problèmes de performance. Elle pose les bases pour les chantiers suivants.

Le Lot 2 — Chantiers Structurants (18 jours) sécurise l'application à moyen terme : mise à jour de Rails et des bibliothèques, refonte des parties les plus fragiles, augmentation des tests. L'investissement total recommandé est de 23 jours sur 2 à 3 mois.

Observations préliminaires

  • Architecture hybride : Application configurée en api_only mais inclut ActiveAdmin (views ERB, assets CoffeeScript/SCSS).
  • Authentification double : Devise pour les admin_users, authentification par token custom (AccessToken) pour l'API mobile.
  • GraphQL : Endpoint /graphql exposé, GraphiQL activable via ENABLE_GRAPHIQL.
  • Dépendances : Rails 6.0 en EOL (juin 2023), coffee-rails obsolète, mandrill_mailer, spring.
  • Cache : Dalli présent mais config.cache_store commenté en production.

Findings

🔴 SEC-001 — CVE GraphQL : exécution de code à distance▼

Critique Effort : S (2-8h) | Vendabilité : ⭐⭐⭐

Localisation : graphql gem (2.0.14)

Constat : CVE-2025-27407 — La gem graphql permet l'exécution de code à distance lors du chargement d'un schéma GraphQL malveillant.

Recommandation : Mettre à jour graphql vers ≥ 2.0.32 : bundle update graphql

🔴 SEC-002 — SSL désactivé en production▼

Critique Effort : XS (< 2h) | Vendabilité : ⭐⭐⭐

Localisation : config/environments/production.rb

Constat : config.force_ssl = true est commenté. Les requêtes HTTP ne sont pas redirigées vers HTTPS.

Recommandation : Décommenter la ligne : config.force_ssl = true

🔴 SEC-003 — CVE ActiveAdmin : XSS stocké et injection CSV▼

Critique Effort : M (1-3j) | Vendabilité : ⭐⭐⭐

Localisation : activeadmin gem (2.12.0)

Constat : CVE-2024-37031 (XSS stocké), CVE-2023-51763 (Injection CSV)

Recommandation : Mettre à jour ActiveAdmin vers ≥ 3.2.2 ou ≥ 4.0.0.beta7

🔴 SEC-004 — CVE ActiveRecord : injection SQL▼

Critique Effort : S (2-8h) | Vendabilité : ⭐⭐⭐

Localisation : activerecord (6.0.6)

Constat : CVE-2023-22794 — Vulnérabilité d'injection SQL via les commentaires ActiveRecord.

Recommandation : Mettre à jour Rails vers ≥ 6.1.7.1 (ou 7.x)

🟠 SEC-005 — Log level debug en production▼

Majeur Effort : XS | Vendabilité : ⭐⭐⭐

Constat : config.log_level = :debug expose des informations détaillées dans les logs.

Recommandation : Utiliser config.log_level = :info ou :warn

🟠 SEC-006 — CORS mal configuré▼

Majeur Effort : XS | Vendabilité : ⭐⭐

Constat : origins 'example.com' — valeur placeholder. Configurer les origines réelles via ENV.

🟠 SEC-007 — Absence de Content Security Policy▼

Majeur Effort : S | Vendabilité : ⭐⭐

Constat : Aucune CSP configurée. Créer config/initializers/content_security_policy.rb

🟠 SEC-008 — Secrets development/test en clair▼

Majeur Effort : XS | Vendabilité : ⭐⭐

Constat : secret_key_base pour development et test en clair dans secrets.yml.

Recommandation : Utiliser ENV["SECRET_KEY_BASE"] pour tous les environnements.

🔴 PERF-001 — Absence de la gem Bullet pour détecter les N+1▼

Constat : Aucun outil pour détecter les requêtes N+1 en développement.

🟠 PERF-002 — N+1 potentiels dans les types GraphQL▼

Majeur Effort : S | Vendabilité : ⭐⭐⭐

Localisation : OrderType, ClientType, QueryType

Constat : OrderType expose client, products, subscription sans includes. Chaque order charge séparément ses associations.

Recommandation : Utiliser GraphQL::Batch ou précharger avec includes dans les résolveurs.

🟠 PERF-003 — Cache store non configuré en production▼

Majeur Effort : S | Vendabilité : ⭐⭐

Constat : config.cache_store = :mem_cache_store est commenté. Rails utilise :memory_store par défaut.

Recommandation : Configurer :mem_cache_store ou :redis_cache_store en production.

🟠 PERF-004 — Pas de fragment caching dans les vues▼

Majeur Effort : M | Vendabilité : ⭐⭐

Constat : Aucun cache do ... end dans les vues. Les vues Admin et API sont régénérées à chaque requête.

Recommandation : Ajouter cache [model, model.updated_at] pour les fragments stables.

🟠 PERF-005 — QueryType#all_clients : Client.all sans optimisation▼

Majeur Effort : XS | Vendabilité : ⭐⭐

Constat : Client.ordered et Client.all retournés sans includes.

Recommandation : Précharger les associations selon les champs demandés ou utiliser un DataLoader.

Quick wins

  • PERF-003 — Configurer cache_store en production (S)
  • PERF-005 — Précharger associations QueryType (XS)
